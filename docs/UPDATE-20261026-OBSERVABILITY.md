# 配置说明与历史结果展示维护

本次只改进开源版本的说明和状态展示，不改变模型调用、凭据选择、冷却策略、消息投递或官方打卡调度。公开默认仍关闭 AI 和群打卡，群名单为空。

## 为什么单独展示上游观察

临时限流冷却结束后，本机原有逻辑会清空当前错误并解除暂停。这只允许后续新任务，不能证明接口已经恢复；旧错误仍在历史诊断中，但不能只看主状态的“未暂停”。本版新增基于保留诊断计算的摘要，展示最新请求结果、最后失败和最后完整模型响应。无新验证请求，不重发旧题。

历史记录没有当前接口/模型的绑定证明，页面会明确标注这一点。更换配置后，旧失败不会被表述为新配置仍然故障；旧成功也不会被表述为新配置已经可用。HTTP 200 与完整回答、完整回答与 QQ 投递分别判断。本地排队、图片下载和凭据检查不冒充供应商响应。

## 打卡首次业务验证

接口和 PacketBackend 检测保持只读。面板新增账本确认提示：“尚无已确认记录”与“本机账本已有记录已确认”分开显示。请求返回、人工解除后续日期阻止和离线用例均不会被当作确认成功；已有确认也只适用于对应账号、群和日期。每群真实结果仍须查看其记录及日期约束。

## 配置说明

新增 [配置指南](CONFIGURATION.md)，列出模块独立性、字段为 0 的不同含义、分群时间/时区继承、检查精度与网络请求间隔的区别、补打/退避/未知保护及本地设置与供应商限制的边界。没有把零点、某个群或某个个人写成固定规则，也没有增加依赖。

新增合成回归先在旧代码上复现“冷却后没有独立保留的历史结果摘要”，随后验证保留失败、完整流式结束、QQ 投递失败、图片/凭据本地阶段、重载、配置更改和脱敏边界。最终结果见 [测试记录](../TESTING.md)。本次没有对生产目录部署，没有真实模型请求或真实群打卡。
