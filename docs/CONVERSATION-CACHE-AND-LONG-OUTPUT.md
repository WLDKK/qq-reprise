# 会话缓存与长代码回复

会话缓存用于理解当前会话的上下文；不建立长期人物档案，不自动总结，也不使用向量数据库。公开默认关闭。

## 开启与调整

完成 AI 与 QQ 绑定后，在「日常设置 → 最近会话缓存」单击开启。界面会说明：在既有 AI 允许范围内，将之后收到的文字和已确认发送的 AI 回复作为上下文资料，发送给当前已配置的服务及模型。保存不调用模型。更换服务端点、接口格式、模型或绑定账号后，原缓存授权不继续生效，需要重新选择。

「完整设置 → 缓存、历史与消息定位」可以修改每会话容量、总条数、总字节、单条长度、保留时间、优先近期条数、相关较早条数及单次输入字符预算。下列是可采用的配置示例，不会自动覆盖已有用户设置：

| 项目 | 示例 | 含义 |
| --- | ---: | --- |
| 每会话缓存容量 | 500 条 | 消息条数，不是 500 个会话或 500 轮问答 |
| 总消息容量 | 5000 条 | 本功能所有会话合计，超出淘汰最早消息 |
| 总正文容量 | 8 MiB | 超出时可能在达到 500 条前先淘汰 |
| 优先近期消息 | 12 条 | 与相关较早消息交错选择，不保证全部进入请求 |
| 相关较早消息 | 最多 12 条 | 按本地文字相关性从缓存中选择 |
| 历史与背景总预算 | 16000 字符 | 与缓存容量独立；不是 16000 token |
| 群背景预算 | 8000 字符 | 仍受历史与背景总预算约束 |

现有群引用缓存与本功能缓存分别在 RAM 中维护，均受其容量约束；图片定位、撤回缓存、已确认问答也有独立设置。普通的问答轮数仍控制近期已确认问答，本功能可以补充八轮以外、仍在消息缓存中的相关内容。

## 范围与删除

- 按登录账号、群/私聊及会话对象分隔；说话人用当前会话内的匿名标签标明。其他成员的话不当作当前提问者的话。
- 只使用当前已允许 AI 参与的会话。群成员策略、群聊黑名单、私聊黑名单及私聊回复范围仍生效；不新增群，不扫描历史或旧日志。
- 只缓存通过既有凭据保护检查的文字。图片、附件、文件路径及图片像素不进入这项文字缓存；过长单条消息整条跳过，不把半截代码当完整历史。
- 收到撤回通知后删除对应缓存，并取消仍依赖它的待处理回答。发给上游的旧请求无法靠本地删除收回。
- 关闭本功能会清空本功能缓存。进程退出、重启或清空运行上下文后，正文不会恢复；已保存的设置保留。
- 请求按到达时的消息序号截取上下文，后来的消息不能串入已经排队的旧问题。缓存资料不是系统指令，不授予文件、账号或 QQ 管理操作权。

## 长代码的预算与发送

普通回答的 API token 预算、本地输出字符上限、历史输入预算互相独立。「平台决定」模式不会发送 `max_output_tokens` 等字段，此时保存的自定义 token 数值不生效。

例如，可针对实际支持较长输出的模型选择「自定义 32768 token」，并将本地输出字符上限设为 200000。32768 是单次生成上限，不是要求每次用满，也不是硬费用上限。模型服务自身的上下文、推理 token、输出、限流与计费规则仍生效。公开默认预算保持保守，使用者按模型能力调整；没有给所有兼容服务强加同一个模型上限。

Responses 使用 `max_output_tokens`；官方 OpenAI Chat Completions 使用 `max_completion_tokens`，其他现有兼容端点按已支持的字段处理。流式正文仍受有限的协议体积与事件大小约束，长回复的 SSE 开销会随字符预算有界扩容，最大 32 MiB。

模型必须完整结束后才发送，超出生成或字符预算不会把半截答案当完整回答发出。QQ 展示转换完成后，长回答按每段最多 3500 个 JavaScript 字符单元拆成传输段，优先在换行处分开；超长单行才在安全字符边界分开。不增加段号到代码正文，不去掉缩进、乘法、指针、下划线或字符串字符。各段文字按顺序拼接可重建完整展示文本。

所有段属于一个逻辑回复，每段单独经过既有发送队列和回执核对。中间失败或结果未知时，不重发前面已确认段；未知段不盲重试，后续段停止。管理页显示「已确认 X/Y 段」及未知/未发送状态。迟到回执只能更新其对应段，不会把第一段回执当作下一段，也不会自动恢复已经停止的后续发送。只有整条回复全部确认，才记为已完成并进入已确认问答、触发可选素材附带发送。

## 验证边界

回归使用合成的 C/C++、Python、中文、表情符号和 CRLF 文本，以及模拟的模型事件流、QQ 回执和浏览器状态。覆盖 500 条淘汰、会话/成员隔离、近期与较早相关内容、撤回、服务切换、语义审查一致性、长代码原文重建、SSE 开销、中途失败、未知与迟到回执。未用真实模型额度、真实群消息或用户图片验收，不能据此宣称所有 QQ 客户端或上游长输出均已联调通过。
