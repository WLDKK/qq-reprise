# 通用识图：接入、验证和图片范围

回响 QQ 助手可为普通 API 配置 Responses 或 Chat Completions 图文请求。**代码支持某种请求格式，不代表任意模型或账号支持图片。** 视觉验证绑定完整服务基础地址（含路径）、协议、模型和验证图片数量；切换其中的服务信息会使原验证失效。模型列表和文字测试不提供视觉证明。

公开配置默认关闭识图、图片引用和近期图片定位，单次图片数默认 1。升级不会自动为一个新服务启用图片外发。原 Discovery 已有的有效记录只兼容原模型的 Chat Completions 单图范围，不会扩展到其他接口或多图。

## 按顺序接入

1. 在“模型与 API”保存自己合法使用的基础地址、协议、模型和凭据。使用服务方提供的模型 ID；仓库不附带 Key 或模型权限。普通 API 的完整草稿保存会保持 QQ AI 关闭，需要时自行重新开启。
2. 在“诊断与高级 → 识图请求限制”设置数量、大小和超时，使用该分区的保存按钮。只改这些限制，不替换凭据或 AI 专用网络配置。
3. 点击“验证已保存的识图配置”。它使用**已保存**的接口、凭据和 AI 网络设置，单次请求只发送按当前数量生成的随机色块图，不上传 QQ 图片、聊天记录或页面未保存的新 Key。不自动重试，也不自动开启识图。此操作会请求供应商，可能计费；本地次数限制不是费用硬上限。
4. 验证通过后，在“识图与图片定位权限”明确开启所需选项并保存。激活操作需要 30 分钟内的当前组合验证；已经持久化开启的同组合权限不会因浏览器刷新自动失效。提高数量后必须重新验证，原权限会关闭。
5. 只有需要真实 QQ 联调时，才在自己获准的测试会话发一条图片消息并按既有唤醒规则提问。先核发送者和会话范围，再确认下载、模型响应和 QQ 投递；本文和离线测试不代表这些真实链路已经成功。

合成验证要求模型按图片顺序给出随机色块答案。通过只说明该次图文请求和答案匹配，不保证所有图片、OCR 内容、复杂题目或供应商未来行为都正确。失败时界面保留阶段、HTTP 状态或允许的错误类别，不把文本回应冒充识图成功。

## 协议与当前支持范围

| 项目 | 行为与边界 |
| --- | --- |
| Responses | 当前消息使用 `input_text` 与 `input_image`，图片为经过本地校验的 Base64 data URL |
| Chat Completions | 当前消息使用 `text` 与 `image_url`，Discovery 原接口继续兼容 |
| 一条新消息包含多图 | 按原顺序发送整个合规图片组；数量、单图或总大小超限时整次拒绝，不截取部分图片来猜答案 |
| 明确引用一条多图消息 | 需开启图片引用；只检查该消息 ID，核对当前账号及同一群/私聊范围，核对后才下载图片 |
| 同用户近期图片 | 需另行开启；只定位同账号、同会话、同发送者的一条图片消息/图片组。多个独立候选仍需明确引用，不默认挑最新或拼接历史 |
| 当前图片混合图片引用 | 保持歧义拒绝；将要比较的图片放在同一条消息，或明确引用该条图片组 |
| PNG、JPEG、静态 WebP | 校验文件签名、尺寸和字节上限后使用 |
| GIF、APNG、动态 WebP | 尽力提取一张静态帧；解码失败明确报错，不声称分析完整动画 |
| QQ 内置表情 | 只有编号时作为元数据，不能声称看见像素 |
| 任意附件、本地路径、音频、视频 | 不通过此识图路径读取或理解 |

Responses 与 Chat Completions 的图片字段不同，不能仅删除供应商限制或替换占位文本来完成适配。接口结构参见 [OpenAI 官方图片输入说明](https://developers.openai.com/api/docs/guides/images-vision)。兼容服务是否接受这些字段、支持哪些模型和额度，由服务方决定。

## 可修改的限制

| 配置字段 | 默认 | 可设置范围 |
| --- | ---: | --- |
| `vision_max_images` | 1 | 1–8；增加数量会关闭旧图片授权，需按新数量重新验证 |
| `vision_max_image_bytes` | 5242880 | 1024–5242880 字节（最大 5 MiB） |
| `vision_max_total_bytes` | 5242880 | 1024–20971520 字节（最大 20 MiB），不得小于单图上限 |
| `vision_download_timeout_seconds` | 10 | 1–120 秒，每张下载/处理分别受限 |
| `vision_request_timeout_seconds` | 60 | 1–600 秒；整次引用、下载、预算等待和生成还受普通请求超时的较小值约束 |

字节预算同时检查输入文件和解码后的静态帧，按每张两者的较大值累计；Base64 编码会增加 HTTP 体积，供应商可能有更低限制。像素尺寸仍限制为每边不超过 8192、总像素不超过 2000 万。解码器自身的保护也继续生效。图片定位缓存容量、保留时间和补充指令等待可在原缓存分区独立修改；它们不会解除请求数量/大小限制。

修改图片限制、权限或接口可能清空 RAM 上下文；保存前先等现有生成和待发送任务结束。配置和原有私有绑定持久化，图片像素和定位缓存不作为聊天记录长期保存。

## 路由和隐私

- 图片请求与合成验证复用已保存的 **AI 专用网络设置**，不更改系统代理。QQ/NapCat 和 QQ 图片下载仍使用各自既有连接方式，不被 AI 代理模块接管。设置方式见 [AI 网络说明](AI-NETWORK-AND-TEST.md)。
- 图片只发送给已验证的原 API 连接；主备账户池不为图片切换服务、重试或借用另一连接的密钥。只配置账户池而未配置原连接凭据时，先配置并验证原连接。
- 下载仅接受既有允许的 QQ 图片域名或当前图片段的 Base64 数据，拒绝本地文件、回环/私人主机地址、认证 URL 和重定向；不会跟随供应商回复中的任意图片链接。
- 引用、近期定位和多轮均保留账号/会话边界；模型历史只保留获准文字，不自动重发此前原始图片。不扫描其他群、无关私聊或未知历史。
- 图片可能含无法由文字规则识别的隐私。程序不能保证在像素里找出全部凭据或个人信息。不要上传密钥、账号后台或不获准外传的截图。
- 取消会停止本地等待并请求中断 HTTP；远端是否停止及是否计费不能确认。迟到结果不会激活新模型或覆盖新操作，不自动重试。

## 常见失败

| 提示/阶段 | 下一步 |
| --- | --- |
| `vision_not_verified` | 核对已保存端点、协议、模型和数量，先做明确允许的合成验证，再保存开启 |
| `vision_target_changed` | 当前配置与测试开始时不同；核对新配置后重新操作 |
| `vision_probe_mismatch` | 请求没有匹配随机图像答案；不能视为通过，不自动开启 |
| `vision_image_count_exceeded` / `vision_total_bytes_exceeded` | 调整本次图片或显式修改限制；不会自动丢图继续 |
| `vision_image_download_failed` / 下载 HTTP 错误 | 检查 QQ 资源是否仍有效；这不是供应商 API 的 HTTP 状态 |
| `vision_download_timeout` / `vision_request_timeout` | 分别查看图片下载与整次等待限制；不要反复点击造成重复计费 |
| 模型/API HTTP 400、403、429 | 核对服务方明确返回的能力、权限、限流或额度信息，不猜测 Key 无效或欠费，不切换账号绕过 |
| 图片引用范围未知或多个候选 | 在获准的原会话重新发送一条明确图片组，或明确引用一条可核对的消息 |

本轮验证使用合成图片、模拟 API/QQ 和隔离浏览器；没有上传真实 QQ 图片或调用付费 API。完整证据与未实测范围见 [测试记录](../TESTING.md)。
