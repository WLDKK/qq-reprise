# 合成识图诊断：颜色、请求与上游响应分层

本次改进帮助定位验证失败，不代表已经确认任意模型的视觉能力。HTTP 200、完整输出、成功解析四个颜色，都不能代替四个位置正确匹配。

新的合成验证会保留：按每图左上、右上、左下、右下排列的预期/解析色序；本地准备的 PNG 数量、尺寸、字节数、SHA256；流式响应中的模型标识（若上游提供，只视为自报）。即时结果和详细诊断显示同一份脱敏证据，独立于后台刷新。旧记录缺失的内容不能倒推，失败不会自动改为成功。

记录只对服务端生成的测试色块启用。颜色限定为 red/green/blue/yellow；任意回答正文、认证头、Key、图片 Base64、URL 不会进入这些新增字段。普通用户图片不新增指纹或上述模型字段，识图开关不被自动打开。返回的可疑模型标识或凭据回显会被丢弃。

图片摘要只能证明本地准备的请求内容，不能证明上游接收、解码或使用了像素。上游不返回模型标识时保持未知；不能凭请求型号推断实际后端。色序不正确、缺失或存在歧义仍然失败，不自动重试、不降低标准。

独立 Windows 图像解码器检查全部 24 种排列，24/24 正确；以当前发送模块注入离线 fetcher 捕获两个协议的单图/多图，50/50 的字节、顺序和尺寸正确。这些都是本地合成证据，不是上游联调结果。

最终公开版及保留私有默认值的代码组合分别 736/736 项离线回归通过；新增 15 项覆盖隐私白名单、顺序错误、协议序列化证据、凭据回显、普通图片隔离、持久化与旧失败保留。真实浏览器合成流程 16/16 通过；发现即时结果缺失证据后已补全并复核。未执行真实付费 API、QQ 消息或用户图片上传。

要进一步判断模型识图失败，需用户主动发起新的合成验证并查看新证据；测试可能消费供应商额度。若颜色依旧错误，保留结果，不要通过降低要求或反复点击把它当作成功。
