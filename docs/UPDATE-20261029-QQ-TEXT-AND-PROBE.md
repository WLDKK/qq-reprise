# QQ 纯文本显示与识图校验修复

## QQ 的 AI 回复使用普通文本

QQ 消息窗口不作为 Markdown 页面渲染。本次在 AI 回复生成说明中增加 QQ 展示约定，并在发送端实际转换常见格式，不能只依赖模型遵守提示。

| 输入形式 | QQ 展示与保护 |
| --- | --- |
| `#` 标题、常见粗体/斜体 | 去掉可明确识别的格式标记，保留内容；变量名和 Python 双下划线标识符优先原样保留 |
| 数字、嵌套项目及任务列表 | 保留层次、顺序及项目内容，普通项目和勾选状态转换为文字符号 |
| 代码围栏 | 只去掉外围围栏；逐行保留 C/C++/Python 的缩进、换行、预处理指令、运算符、标识符和字符串内容 |
| 未加围栏的代码 | 对缩进、预处理指令、常见声明/赋值等保守保护；不全局删除 `*`、`_`、`#` 或反引号。建议模型仍用围栏明确代码范围 |
| Markdown 链接/图片引用 | 转为“名称（地址）”或图片文字说明，不下载链接；URL 的括号、下划线、查询参数等内容保留 |
| 规则表格 | 依原表头按行转成逐条“字段：值”，保留全部单元格；不规则表格保留原文，不臆造缺失值 |
| 公式 | 继续转换能可靠表达的简单公式；复杂公式明确保留公式原文，不为去掉标记篡改数学含义 |
| 引用原文 | 引用正文保留原样，添加普通文本引用提示；不会将格式处理应用到输入问题、QQ 撤回缓存或重发原文 |

格式处理只在本次 AI 回复进入发送队列前执行一次，仍组合为一个文字消息段，并与原有结构化提及一起发送；不把代码或公式切成会乱序的独立投递。模型文字历史仍沿用原有权限和校验，不重写已经保存或缓存的用户内容。

这不是完整 CommonMark/HTML 渲染器。极长的单行（超过 65536 字符）或无法无歧义判断的结构会保留原内容，不截断来换取“格式正确”。这些保守回退可能仍含可见符号，优先保证代码、公式和原文不被破坏。

## 合成识图验证不再误拒常见答题格式

旧校验要求颜色答案的原始字符形式几乎完全一致，同一正确色序带反引号、逗号、JSON、代码围栏或列表时也会失败。离线使用同一组合成图片复现为 1/6 通过，修复后 6/6 通过。

新解析允许这些可明确解释的色序表示，但仍要求完整图片数量、颜色与顺序全部匹配。错误色序、缺色、多色、乱序编号及夹带其他说明的模糊回答不会成为视觉证明；没有把“包含几个颜色词”当成成功。

新测试结果仅记录答题格式类别、颜色数和位置匹配数，不记录模型回答原文、图片数据或凭据。HTTP 200 且完整结束只能说明请求与回复完成，不能代替图像校验。失败时区分格式未识别与色序不匹配；旧记录没有这些信息时明确说明无法回溯区分。

升级不会把旧失败记录重新标成成功，不发新 API 请求，也不自动开启识图。用户需自行明确进行一次使用已保存配置的合成验证（可能计费），通过后再保存开启所需范围。模型真实能力、账号权限和真实 QQ 图片链路仍需独立确认，不能由这次离线修复替代。

接口与图片范围见 [通用识图说明](GENERIC-VISION.md)，结果与边界见 [测试记录](../TESTING.md)。
