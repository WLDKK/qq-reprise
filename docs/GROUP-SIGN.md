# QQ 群官方打卡

这是 QQ 群自带的打卡功能，通过 NapCat 的 `send_group_sign` 请求执行，不发送“签到”文字。`set_group_sign` 是同一能力的别名，本实现只调用前者，不在异常后改用别名重复提交。

## 配置与使用

在本机管理页选择“撤回重发 → 官方群打卡”。总开关默认关闭，群列表为空；安装、升级和查看页面都不会自动选择群或签到。

1. 确认 QQ 在线，选择自己的群，点击“添加群（默认不启用）”。
2. 设置每日时间和 IANA 时区。默认 `08:30`、`Asia/Shanghai`；群时间或时区留空时继承全局值。
3. 按需勾选该群和总开关，保存时确认实际范围。启用绑定当前 QQ，切换账号后暂停执行，必须重新核对配置。
4. “现在打卡”需要另一次确认，且要求该群和总开关已启用。该按钮会执行真实打卡；本项目的离线测试和截图均不调用真实群。
5. “只读核对今日记录”和“只读检查接口与 PacketBackend”不提交打卡。

独立匿名配置见 [示例](../examples/group-sign-settings.example.json)。通常直接从页面配置即可；不要用匿名示例覆盖已有私有配置。NapCat、QQ、电脑必须在任务到期时可用，程序不会修改网络、登录、PacketBackend 或系统权限来尝试恢复。

## 如何判定结果

| 状态 | 依据 | 后续动作 |
| --- | --- | --- |
| 发送意图已保存 | 本机去重记录已持久化，即将调用接口 | 意外退出后按未知处理，防止重打 |
| 请求已发送，待记录确认 | `send_group_sign` 调用返回，没有业务成功凭证 | 按配置有限次数只读核对；不再次提交 |
| 记录已确认 | 在下述日期约束内，从记录列表正向找到当前账号 | 当日相同账号与群不再提交 |
| 结果未知 | 超时、连接中断、接口异常、核对次数耗尽或重启中断 | 保留记录，不自动重打 |
| 确认未发送 / 前置检查失败 | 本地 PacketBackend 检查失败，或适配器明确声明尚未提交 | 仅这类结果可有限退避重试 |
| 错过计划，按配置跳过 | 恢复运行时已超过允许执行窗口 | 不自动补打；用户可明确手动执行一次尚未提交的当日计划 |

HTTP 200 / OneBot `ok` 只证明接口接收了请求，不等于 QQ 群打卡已生效。接口拒绝也不能一概证明没有生效。

### UTC 查询日的限制

核查的 NapCat 实现把 `get_group_signed_list` 查询日构造成 **UTC 当天**，只返回第一页。助手去重日则按每群配置的时区计算。例如北京时间 00:00–07:59，这两个日期可能不同：即使列表里有自己的账号，也不能据此确认北京时间当天已签到。

自动正向确认要求：本机 NapCat 连接、可核版本信息、明确选择 `napcat_utc_today` 约定、请求前后 UTC 查询日一致，且与该条去重日期相同，并在第一页找到当前账号。日期错配、查询跨 UTC 午夜、字段不明、缺少本人、远程/未知适配器均保持待确认或未知，不推测时间戳单位，也不据此重打。未核版本或实现变化时应改为 `manual_only`，仅保留待确认记录并自行核实。

## 定时、去重与恢复

- 独立定时检查默认约每秒一次；`scheduler_interval_ms` 可设 250–60000 毫秒，在界面高级策略中实时修改。大间隔、休眠或事件循环阻塞可能错过计划分钟，随后按所选补打策略处理。该设置不改变 QQ/AI 的后台周期，未到点只作本地检查，不发起群接口调用。按配置时区计算当日，不承诺精确到秒。每条去重键为 **登录账号 + 群号 + 日期**，时区修改不会清除同一日期记录。
- 页面显示每群下次计划时间；它仍取决于在线、账号绑定、存储和未知记录策略，不保证打卡排名。夏令时不存在的本地时间会跳过，不伪造执行时间。
- 默认 `missed_policy: skip`：错过计划分钟则跳过当日自动任务。可显式改为 `within_window`，仅在配置分钟窗口内补执行当天计划；不补前一天。
- 默认最多 2 次确定未提交的尝试，指数退避 60 秒起、上限 900 秒；界面可调整。已发送或未知结果不走这条重试通路。
- 手动与定时共用可调的有界调度：并行任务上限 1–4，启动间隔 250–60000 毫秒，默认 1 / 500 毫秒。网络等待不占用账本进程锁；先在锁内保存去重预留及发送意图，再调用接口。重启时未完成的意图或待确认提交转为未知，保留去重。
- 默认前一日期存在未处理的未知结果时暂停该群后续日期。可以人工核对后解除这个阻止，或显式选择允许新日期；旧未知记录仍保留，不重发旧日期。
- 系统时钟显著回退时停止新增操作，等时间追上已记录时间。存储损坏或无法持久化时只暂停打卡功能，不把账本清空后继续。

配置独立保存在 `group-sign-settings.json`；去重和脱敏错误类别在 `group-sign-ledger.json`。这些是私有运行数据，包含账号、群、日期，不能上传。默认保留已结束记录 90 天、最多 2000 条；未处理的未知记录不因保留期自动删除。移除群计划不会删除其账本，容量不足时暂停新增操作。不要删除账本来强制重试。

## 接口来源与验证边界

协议事实参考 [NapCat API 文档](https://doc.napneko.icu/develop/api)、[SetGroupSign](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/action/extends/SetGroupSign.ts) 和 [GetGroupSignedList](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/action/extends/GetGroupSignedList.ts)。接口依赖 PacketBackend；不同版本、账号、群权限或 QQ 服务状态可能使它不可用。本项目没有打包或复制 NapCat 实现。

验证使用合成账号、日期、接口与隔离本机 HTTP 服务，覆盖默认关闭、权限与账号绑定、同日并发、重启/睡眠/跨日、UTC 边界、记录首屏缺失、超时和迟到结果、有限退避、持久化失败及页面流程。**未执行真实群打卡，也未验证所有 NapCat / QQ 版本的业务成功回执。** 检查与调用计数只描述本服务，不代表 QQ 业务成功。修复说明见[本轮维护](UPDATE-20261026.md)。完整计数见 [测试记录](../TESTING.md)。
