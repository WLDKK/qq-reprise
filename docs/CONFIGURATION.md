# 配置与状态核对

本页说明现有设置如何组合，以及哪些状态可以作为证据。配置不绑定某个固定群、每天零点或特定个人；公开示例关闭主动功能，使用者自行选择范围和时间。

## 分别配置各项功能

| 功能 | 配置入口与文件 | 与其他功能的关系 |
| --- | --- | --- |
| 撤回监控与重发 | 撤回重发页；`config.json` | 选择目标群/好友及重发开关，不会替 AI 或打卡授权群范围 |
| AI 普通回复 | AI 工作台；`ai-settings.json` | 总开关、QQ 绑定、群/成员/私聊范围、触发方式与接收方分别保存 |
| AI 主动参与 | AI 设置中的主动参与区 | 独立启用；逐群已填规则覆盖该项通用默认，但全部群预算、账户预算仍生效；不替普通回复更改权限 |
| 群背景外发 | AI 群背景设置 | 需要单独启用并绑定当前 API 接收方；本地缓存不等于允许外发 |
| API 连接池 | 连接管理；`ai-connections.json` | 配置连接不等于启用路由；主连接、备用与开关均需明确保存；多个 Key 不代表多个独立供应商配额 |
| 官方群打卡 | 撤回重发页内的独立打卡面板；`group-sign-settings.json` | 独立总开关、群名单、时区、时间和账本，不依赖 AI 开启或某次撤回事件 |

如果要对同一组群启用多项功能，应分别核对它们的名单。打卡名单不随撤回或 AI 名单自动增删。不要把旧运行目录整包复制进公开仓库；私有文件边界见 [排除清单](../PUBLISH-EXCLUSIONS.md)。

首次安装可复制 [撤回示例](../examples/config.example.json)、[AI 示例](../examples/ai-settings.example.json)。打卡示例为 [group-sign-settings.example.json](../examples/group-sign-settings.example.json)。已有配置升级时保留原文件；只从页面调整需要的字段，保存后刷新页面核对。修改配置前先查看正在生成、待发送及结果未知的任务，不依赖配置保存来处理旧投递。

## 常见“0”的含义

不同字段的 0 有不同意义。只有该字段明确允许时才可以填 0；页面和配置校验器会拒绝越界值。

| 设置 | 0 的含义 | 仍然生效的边界 |
| --- | --- | --- |
| `context_turns` | 不保留问答历史 | 当前输入与其他显式允许的来源仍各自受限 |
| `context_ttl_minutes` | 会话和图片定位不按时间淘汰 | RAM 容量、会话数量、图片容量、退出/重启清空 |
| `group_cache_ttl_minutes` | 群缓存不按时间淘汰 | 每群及总条数、字节预算；外发授权不因此开启 |
| `daily_requests` | 不设本机每日生成任务次数上限 | 账户池、主动参与预算以及供应商计费/限流；此计数不是 HTTP 请求次数 |
| `queue_wait_seconds` | 不另加基础排队等待 | 前序任务预算、容量与排队到期仍按队列规则处理 |
| `temporary_recovery_attempts` | 不设本地解除临时限流暂停的次数上限 | 不会自动重发旧题，不会凭此增加供应商额度 |
| `confirmation_checks`（打卡） | 不自动查询打卡记录 | 已提交仍不等于已确认；可分别使用只读核对或在 QQ 中自行核实 |

普通回复的字符上限、输出 Token 设置、请求超时和主动参与预算分别控制。`api_output_token_mode: platform_default` 表示本次请求不附带本地输出 Token 参数；它不取消供应商默认上限、本机字符上限或请求超时。不能仅通过提高某个本地值扩展模型本身的上下文、图像能力或账号权限。

## 独立打卡参数

| 参数 | 含义与范围 |
| --- | --- |
| 总开关、分群开关 | 两者都启用，且当前账号与绑定一致，才允许提交 |
| `default_time`、`timezone` | 全局每日时间 `HH:MM` 与 IANA 时区；公开默认 `08:30` / `Asia/Shanghai`，均可修改 |
| 每群 `time`、`timezone` | 非空值覆盖全局；空白继续继承，不复制成固定值 |
| `scheduler_interval_ms` | 250–60000ms，默认 1000ms；独立本地检查精度，未到点不发群请求，不改变其他后台周期 |
| `dispatch_concurrency`、`dispatch_interval_ms` | 并行任务 1–4；任务启动间隔 250–60000ms；与本地检查精度分别设置 |
| `missed_policy`、`catch_up_minutes` | 默认错过跳过；`within_window` 可在 1–1439 分钟窗口内补当天，不补前一天 |
| `retry_attempts`、`retry_base_seconds`、`retry_max_seconds` | 仅确定未提交时允许 1–5 次有界尝试；起始退避 1–3600s，上限 1–86400s，且上限不能小于起始值 |
| `confirmation_mode`、查询间隔及次数 | `napcat_utc_today` 受 UTC 日期和首屏限制；`manual_only` 不自动查询；查询不会再次提交打卡 |
| `previous_unknown_policy` | 默认 `pause_group`；显式 `allow_new_day` 只允许后续新日期继续，不重打旧未知日期 |
| `retention_days`、`record_limit` | 1–3650 天、10–10000 条；未解决记录不会为腾空间而静默删除 |

在当前分钟之后启用并选择 `skip`，当日不会自动补打。检查面板中的下次执行时间，以保存后的计划为准。选择零点只是可编辑的一个例子，不承诺执行排名。电脑休眠、QQ 离线和事件循环阻塞均可能延迟检查。完整日期边界与首次核对步骤见 [群打卡说明](GROUP-SIGN.md)。

## AI：本地状态与历史请求分别看

“AI 已开启 / 本地未暂停”描述本机能否接收后续任务。它不证明供应商可用，也不证明新输入已经生成或发送。临时限流冷却到期会解除本地暂停，**不会自动向上游发一次验证请求，也不会重发旧题**。

“上游历史观察”从已有脱敏诊断计算，不新增网络请求：

- 显示最近观察到的请求结果，同时保留窗口内的最后失败和最后完整响应。
- 排队、本地拒绝、凭据尚未读取或图片下载失败，不冒充一次新的模型 API 响应。
- HTTP 200 头部不等于回答完整；必须有完整结束标志和正文。模型响应完整与 QQ 发送成功分别显示。
- 旧记录没有保存当前配置的绑定证明，因此始终标注“历史记录未绑定当前接口或模型”。更换模型、地址或凭据后，不能自动断言旧记录就是新配置的结果。
- 摘要只包含已有的时间、阶段、状态码、允许的错误类别和投递状态；不增加聊天正文、密钥、接口地址或长期聊天记录。

需要判断一次无回复时，按“收到消息 → 触发/权限 → 排队 → 上游请求/响应 → 完整回答 → QQ 投递”核对最近记录。429 的具体 RPM、TPM、额度或容量原因需要供应商明确字段，不能猜测欠费。一次人工接口测试会产生真实上游请求，是否收费由供应商决定；离线回归不会调用模型。恢复入口与边界见 [README](../README.md#429暂停与恢复)。

## 验证与限制

本版的新增观察摘要、页面状态和配置组合使用合成数据验证。公开仓库不附带任何生产名单、首次真实打卡记录或供应商账号诊断。实际验证情况见 [测试记录](../TESTING.md)；将页面打开、离线测试通过或接口检测通过，都不能当作真实 QQ 与供应商端到端成功。
