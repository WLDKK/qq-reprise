# 按症状排查

先看当前实例与当前配置的时间线。以下步骤不会要求替换账号、盲目重试消息或清空账本。需要真人确认登录或发生真实模型/群请求的操作应分别决定。

| 看到的现象 | 先核对什么 | 结论边界 |
| --- | --- | --- |
| `node` 命令不存在 | 安装位置与新开的终端是否能运行 `node --version` | 不是 QQ、API Key 或网络故障 |
| WebSocket / fetch 等不存在 | 离线自检的具体失败项、Node 版本以及禁用内置功能的启动参数 | 单看版本号不足以证明功能可用 |
| 管理页拒绝连接 | 本次助手终端是否仍在运行、正在使用的完整地址与端口 | 旧 `.instance.json` 或旧浏览器标签不证明进程还活着；不因此删除凭据 |
| QQ/NapCat 已登录但助手未连接 | 正向 WebSocket、本机地址/端口、启用状态和本机 Token 配置 | 不把聊天客户端在线当成 OneBot 可访问的证明 |
| QQ 要求扫码或本人验证 | QQ/NapCat 明确给出的交互提示 | 由本人处理；不要绕验证、切换陌生账号或改安全设置 |
| PacketBackend 不可用 | NapCat 与 **QQ 实际运行构建/架构** 的兼容信息 | `QQ.exe` 文件版本可能不同于热更新后的构建；QQ 在线仍可能不支持打卡接口 |
| AI 开启但没有回复 | 收到 → 触发/权限 → 排队 → 请求/响应 → 完整回答 → QQ 投递 | “开启”或“本地未暂停”不是端到端成功 |
| 429 / 临时冷却结束 | 最近错误类别、可用的 `Retry-After`、供应商侧对应请求时间的额度/限流记录 | 冷却结束不发验证、不补发旧题；不能仅凭429断言欠费、RPM或TPM |
| 401 / 403 | 当前接收方绑定、提供方明确错误类型与账号资格 | 不把授权错误直接归因于电脑断电、VPN或密钥池容量；不要轮换账号规避限制 |
| HTTP 200 但回答没完成 | 完整结束标志、`finish_reason`、输出长度/Token模式与请求超时 | 平台默认预算不等于无限输出；200头部不能证明完整回答 |
| 模型完成但 QQ 投递未知 | 该条原始任务的投递与迟到回执 | 不能当作“未发送”再补发；先核对原会话或只读状态 |
| 图片失败而文字可用 | 当前接口/模型是否适配，是否已明确授权图片外传；失败是在图片下载还是模型请求阶段 | 不把图片资源HTTP错误当作模型API状态码，不宣传任意模型均可识图 |
| 打卡已发送但未确认 | 原账号、群、业务日期、只读查询日期与本人的正向记录 | 接口返回或人工解除后续日期阻止不等于业务成功 |
| 午夜打卡报日期未核实 | NapCat 查询使用 UTC 今天，而群计划可能使用 Asia/Shanghai | 北京时间00:00–07:59可能日期不一致；不应因此重打 |
| 设为0仍存在限制 | 查看该字段的具体0值含义及供应商/共享预算 | 0不统一表示无限，也不自动扩大权限，见[配置指南](CONFIGURATION.md) |
| 重启后上下文或图片定位消失 | RAM内容与持久配置/账本的区别 | 配置文件保留不等于完整聊天历史可恢复 |

## 先看哪一条 AI 证据

管理页中的“上游历史观察”保留窗口内的最后失败和完整响应。它使用已有诊断，不新增请求。排队、本地拒绝、图片下载和凭据阶段不会冒充一次模型 HTTP 响应；模型返回完整与 QQ 送达也分别记录。

旧诊断没有当前接口/模型的绑定证明。使用者更换模型、地址或凭据后，旧失败不代表新配置仍坏，旧成功也不证明新配置已验证。需要实测时，单独决定是否运行一次当前配置的接口测试；该操作可能计费，不属于离线自检或离线回归。

## 午夜之后怎样确认打卡

既有 `get_group_signed_list` 适配按 UTC 当天查询且只有首屏。以 Asia/Shanghai 为例，零点提交属于本地新一天，查询日可能还是前一天；`sign_record_date_unverified` 表示没有足够的同日证据，不表示必然失败。

最早北京时间08:00后日期对齐，可在08:01后使用“只读核对今日记录”，核对**同一绑定账号、群与业务日期**。已耗尽的自动核对不会自行等到08:00再启动；查询不是重打。只有同日正向找到本人才可确认；首屏没有本人仍不能判失败。也可由使用者在 QQ 客户端核对当天的实际记录。

未知记录保留原去重键，不清账本、不调用另一个打卡别名来重试。服务端精确打卡时间或排名未出现在可靠证据中时，不作推测。完整约束见 [群打卡说明](GROUP-SIGN.md)。

## 提交一个可处理的问题

先运行 `node scripts/check-environment.mjs --json`，再按下面格式提供最少信息；不必上传整个运行目录：

```text
功能：撤回 / AI / 官方打卡
环境：Windows与Node版本；NapCat版本、QQ实际运行构建（若相关）
现象与期望：
复现步骤：使用合成文字，单群或多群范围，不填群号或账号
时间与时区：
最后到达的阶段：收到 / 触发 / 排队 / 请求 / 响应 / 完整回答 / 投递
脱敏错误类别或状态码：
是否有未知投递：有 / 无 / 不确定
```

不要附带密钥、Token、OAuth回调链接、昵称绑定、真实聊天正文或完整控制台日志。已有公开示例、受控合成输入及固定错误类别通常更有助于复现。离线测试入口是 `node run-offline-tests.mjs`，它不使用生产凭据；若隔离守卫拦截，保留错误并检查测试范围，不关闭守卫来凑通过。

## 草稿测试和代理

“正在测试”应同时显示本次阶段与耗时；本机校验/HTTP 错误会收尾，刷新不再阻塞结果。取消仅表示本机停止等待并请求后端中止，远端停止/费用仍可能未知；不要反复点击或把未知结果自动重试。

代理问题先核独立 AI 网络模式和当前客户端的 HTTP/Mixed 监听端口，不沿用他人的端口。环境模式读取助手进程环境，不自动读取 Windows 系统代理/PAC；缺少变量不会静默改走直连。新模式需要 Node 24.14+，认证 URL/SOCKS 不支持。API Base URL 保持真实供应商地址，QQ/NapCat 回环连接不经过新 AI 网络层。支持范围与明确错误见 [AI 网络与测试](AI-NETWORK-AND-TEST.md)。

## 识图验证和多图错误

先核对“已保存配置”，再核对识图范围，不要把未保存的接口或 Key 草稿当作合成验证目标。图片授权缺失、目标切换、数量限制和 `vision_probe_mismatch` 的处理见 [识图排查表](GENERIC-VISION.md#常见失败)。下载 HTTP 错误与模型 HTTP 错误分别记录；超出数量或累计字节时整次拒绝，不静默丢图。取消或超时不代表远端一定未计费，没有自动重试。

### 回答超出字符上限 / 长回复仅发出部分

管理页提示“回答超过本机输出字符上限”表示本地字符预算触发，可能已经收到HTTP200，不能等同网络断开或API token不足。分开核对API预算模式、实际发送的token字段和本地字符上限。长回复会保序分段，查看已确认X/Y段、当前未知段及后续停止状态；不要手动重发整段来试错。[说明与配置](CONVERSATION-CACHE-AND-LONG-OUTPUT.md)。
